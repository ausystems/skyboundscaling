# Miami SEO Playbook: Skybound Scaling

The operating document for the Miami ecosystem built into this site. Everything here
is either already implemented in the codebase (marked BUILT) or is an operational task
that happens outside the code (marked OPS).

Positioning (used on every Miami page): We help Miami businesses attract more
customers, generate qualified leads, and scale revenue through websites, advertising,
SEO, automation, and complete digital growth systems. Not a web design shop. Complete
customer acquisition systems, measured against revenue.

Core rules enforced across the build: no doorway pages, no city-name-swap pages,
every page has one unique purpose and search intent, keywords used naturally, no em
dashes anywhere, humans first, one clear conversion goal per page, no ranking
guarantees anywhere.

## 2. Internal linking map (BUILT)

- Homepage: general positioning (no city per current direction); links to Services,
  Work, Blog in nav; Locations (both hubs) via footer.
- Locations index: cards to Miami hub, West Palm Beach hub, county guides, Ontario
  guides; channel-guide aside links every Miami and WPB service page.
- Miami hub links: all 7 Miami service pages (cards + aside), all 7 industry pages
  (rows + aside), 4 blog posts (aside), pricing, contact, work.
- Every Miami service page links: hub, its global /services/ counterpart, 2 to 4
  sibling Miami services, 1 to 2 industry pages, 1 to 2 blog posts, contact/pricing.
- Every industry page links: hub, 3 to 4 Miami services, sibling industries in its
  cluster (trades cluster: roofing, HVAC, contractor), a blog post, contact.
- Every blog post links its money page within the first third, related posts, and
  ends with a contact CTA.
- Anchor text is always descriptive: "Miami Google Ads management", "Miami SEO
  services", "conversion-focused web design", "lead generation systems".

## 4. Technical SEO (BUILT unless marked OPS)

- robots.txt allows all, points to sitemap.xml. BUILT
- sitemap.xml regenerated to include every page with lastmod and priorities. BUILT
- Self-referencing canonicals on every page; directory URLs use trailing slash. BUILT
- Schema: shared Organization + ProfessionalService node on every page; Service +
  FAQPage + BreadcrumbList per Miami page; Article + FAQPage + BreadcrumbList per
  post; ItemList on hubs. All JSON-LD validated by script. BUILT
- Open Graph + Twitter cards on every page, og:locale en_US. BUILT
- One h1 per page, semantic heading hierarchy, skip link, aria labels. BUILT
- Mobile: responsive layout, reduced-motion support, no-JS fallbacks. BUILT
- Core Web Vitals: self-hosted font preload, deferred JS, no render-blocking
  third parties, particle scenes skip gracefully. Images: existing assets are
  compressed; new pages introduce no new image weight. BUILT
- Host-level (from README launch checklist): Brotli, immutable asset caching,
  301 http to https and www to apex, 404 wiring, security headers. OPS
- Google Search Console: submit sitemap after deploy, monitor coverage. OPS
- Rich results test the Miami hub, one service page, one industry page, one post. OPS

## 5. Local SEO operations (OPS: cannot be done in code)

1. Google Business Profile for Miami: exact name Skybound Scaling, category
   Marketing agency, secondary Internet marketing service and Website designer,
   service areas Miami-Dade cities, services list mirroring the 7 Miami services,
   description drawn from the hub hero, UTM-tagged website link to /locations/miami/.
2. Review engine: ask every client at the moment of a win; respond to every review;
   never buy or gate reviews. Velocity beats totals.
3. Citations: consistent name, address, phone across Google, Apple Maps, Bing
   Places, Yelp, BBB, Clutch, UpCity and marketing directories.
4. The site currently publishes no street address by design. When a Miami address
   exists, add it to the Organization schema, the footer, and GBP together.

## 6. Conversion framework (BUILT)

Every Miami page ships with: hero promise + Book a call CTA, proof band (4.2x ROAS,
$42M tracked, senior-run), mid-page contextual links to pricing and contact, FAQ
section answering objections, related-pages asides, and a final CTA panel. The
contact page carries the form (wire data-endpoint per README) plus mailto fallback.
Recommended OPS additions: a Calendly or SavvyCal embed on /contact.html and a
tracked phone number in the header once call tracking is provisioned.

## 7. Measurement (OPS)

- GA4 + form-submit conversion event + call tracking number pool.
- Rank tracking: the primary keyword set above, tracked from Miami geo.
- Monthly report: leads by source, cost per lead by channel, revenue attributed.

## 8. What we deliberately did NOT do

- No doorway pages: smaller Miami-Dade areas (Hialeah, Homestead, Cutler Bay) are
  covered inside existing content, not as standalone thin pages. Add standalone
  pages only when there is unique substance (local proof, reviews, projects).
- No fabricated testimonials, review counts, or client names.
- No guaranteed rankings anywhere, including FAQ answers.
